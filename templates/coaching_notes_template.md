# Coaching Notes Template

## Purpose

Provides the canonical structure for session notes exported by `workflows/export_notes.md`. Variables in `{{double-braces}}` are replaced from cauldron state at export time.

## When to Use

Used exclusively by `workflows/export_notes.md` in Step 2. Not intended for direct user editing — modify the template here and re-run export to regenerate.

## Template Usage Notes

- All `{{placeholders}}` are replaced at export time from cauldron files
- Gap entries repeat dynamically — one section per gap
- "Re-explanations Used" section is omitted if no concepts needed re-explanation
- "Adjacent topics" is populated only if the walkthrough surfaced clear adjacencies (e.g., "this would pair well with X")
- Footer attribution can be customized via a config file (future enhancement)

## Examples

A populated notes file for a PaperCut RCE coaching session would look like:

```markdown
# Coaching Session: PaperCut RCE Chain Walkthrough

**Date:** 2026-05-11
**Duration:** ~52 min
**Final state:** complete

## Baseline Calibration
| # | Prerequisite | Initial Signal | Notes |
|---|--------------|----------------|-------|
| 1 | XML-RPC | 🟢 | Referenced freely |
| 2 | SHA-256 hashing as auth | 🟢 | Referenced freely |
| 3 | Java reflection | 🟡 | Framed on first use |
| 4 | Rhino sandbox | 🔴 | Pre-explained from JS-engine fundamentals |
| 5 | Windows LocalSystem | 🟢 | Referenced freely |

## Walkthrough Chain
1. **The bad password (hardcoded vendor key)** — 🟢
2. **IP ACL bypass (default-allow)** — 🟢
3. **Mint a session + register device** — 🟢
4. **Plant the device script (admin UI)** — 🟢
5. **Fire the hook via authenticateUserWithPassword** — 🟡 → re-explained via "validator vs executor" angle → 🟢
6. **The sandbox escape (reflection)** — 🔴 → traced to Java reflection fundamentals → rebuilt via "objects-that-know-themselves" analogy → 🟢
7. **Why SYSTEM** — 🟢

## Gap Map
### Gap 1: Reflection mechanics
- Triggered at: Sandbox escape concept
- Traced to: How Java objects expose their own methods at runtime
- Rebuild approach: Concrete example with `getClass().getMethod()` walked step by step
- Status: resolved
- Notes: "Objects in Java can describe themselves — that's reflection"

## Key Mechanisms Learned
- **Hardcoded vendor key** — universal across all PaperCut installs; recovering it from any MFD firmware authenticates everywhere
- **Default-allow ACL** — empty config keys often mean allow-all, not deny-all
- **Validator ≠ Executor** — code inside a function isn't executed during validation; only top-level
- **Reflection escape** — once you can reach any Java object, you can reach any class via getClass().getClassLoader()
- **ClassShutter** — the Rhino API that would have blocked the escape; the bug is its absence

## Follow-Up Study
### Gaps to revisit
- (none — all gaps resolved)

### Adjacent topics worth exploring
- Other JVM sandbox escapes (Nashorn, Groovy) — same reflection pattern
- Tanuki Service Wrapper LocalSystem default — common pattern in Java services on Windows
```
